# One-click VMC retarget setup + scene lint (UE 5.6+)

Editor tooling that automates [ik-retargeter-pipeline.md](ik-retargeter-pipeline.md) /
[ik-retargeter-asset-setup.md](ik-retargeter-asset-setup.md) end-to-end, and detects the
misconfigurations we hit while building that pipeline by hand. Lives in `VRM4UCaptureEditor`
(`VrmRetargetSetupUtil`, `VrmSceneLint`, `VrmRetargetSetupMenuExtension`).

## The wizard — "VRM4U: Auto-Setup VMC Retarget"

**Where:** right-click a MetaHuman/DAZ/Mixamo/CC4/… actor in the level → the entry appears
when the actor carries a retargetable (non-native-VRM, has-legs) skeletal mesh.
It is hidden for native VRM actors (those are VMC sources, not targets).

**What it does, in order:**
1. Finds the live VRM source in the level (native VRM bone naming preferred over
   AutoPopulate-meta-only matches, so a DAZ with a meta table is never picked as source).
2. Reuses an existing retargeter for the pair if one exists (e.g. the hand-built
   `RTG_<yourVRM>_to_MetaHuman`), healing a zero-offset retarget pose if found — otherwise:
3. Finds-or-creates the **source IK rig**. Existing rigs are reused only when their chain
   names are the engine-standard set (`LeftClavicle`, not `LeftShoulder` — exact chain
   mapping is by name). Otherwise a new `IK_<mesh>_VRM4U` is built from the VRM humanoid
   table (meta table → humanoid-renamed bones → J_Bip), with clavicle + all finger chains.
4. Finds-or-creates the **target IK rig**: engine auto-characterizer
   (`ApplyAutoGeneratedRetargetDefinition`) for known rigs (MetaHuman/UE5, DAZ, Mixamo, CC4,
   Xsens, …); the VRM chain builder when the target resolves as a VRM humanoid (incl. a DAZ
   with an AutoPopulate meta table — its table is reused to pick the right bones).
5. Creates `RTG_<src>_to_<tgt>_VRM4U`: rigs are assigned **before** `AddDefaultOps()`, so the
   stale-per-op-IK-rig trap (ops baked against the wrong rig) is structurally impossible.
   Then `AutoMapChains(Exact)` and a **`VRM4U_AutoAligned`** target retarget pose via
   `AutoAlignAllBones` (the Step-3.4 bind reconciliation; "Default Pose" kept for rollback).
6. Sets the component's Anim Class to `VrmVMCRetargetAnimInstance` (transactional). At play
   time its auto-resolve wires SourceMeshComponent + Retargeter with zero Blueprint work.

Everything is also callable headless from editor Python:
```python
import unreal
report = unreal.VrmRetargetSetupUtil.setup_retarget(src_mesh, target_mesh, "/Game/MyFolder")
for m in report.get_editor_property("messages"): print(m)
```
New assets are marked dirty, not saved — save them yourself. Nothing existing is modified
except (documented in the report) adding + activating an auto-aligned pose on an RTG whose
current target pose had zero offsets.

## The face wizard — "VRM4U: Auto-Setup VMC Face (LiveLink)"

The body wizard above transfers **bones only**. Its sibling entry (same actor context menu,
shown when the actor carries a MetaHuman `Face_Archetype` mesh or a component named `Face`)
wires the **face**: it assigns the template's stock `ABP_MH_LiveLink` to the face mesh
(existing LiveLink-consuming face ABPs are kept) and adds a `UVrmVMCFaceLiveLinkComponent`,
which at play time republishes the VMC blendshape stream as a LiveLink ARKit subject and binds
it into the face anim instance. Full design: [vmc-face-livelink-bridge.md](vmc-face-livelink-bridge.md).
Headless: `unreal.VrmRetargetSetupUtil.setup_vmc_face_for_actor(actor, "VMCFace")`.

## The lint — "VRM4U: Lint VMC Scene" (Tools menu)

Checks every skeletal mesh component in the level; each finding carries a fix hint. Also
headless: `unreal.VrmSceneLint.lint_world_and_log(world)` (returns finding count; details
in `LogVRM4UCaptureEditor`).

| CheckId | Severity | Meaning |
|---|---|---|
| `VmcNodeOnNonVrmRig` | Error / Warning | A direct VMC anim node drives a rig whose own bones aren't VRM (meta-table-only rigs count as non-VRM on purpose). Severity is decided by MEASURING the bind arm elevation: A-pose bind (MetaHuman/DAZ) → Error, T-pose bind (Mixamo, our gold standard) → heads-up Warning only. |
| `VmcNodeInPostProcess` | Error | A VMC node sits in a mesh asset's post-process AnimBP. |
| `ZeroOffsetRetargetPose` | Error | An RTG targeting a level mesh has a zero-offset current target pose (arms ride ~45° low). |
| `StalePerOpIKRig` | Error | An op resolves chains against a different rig than the asset target. |
| `ChainMappingEmpty` / `LimbChainUnmapped` | Error | No/partial chain pairs on the best-mapped op. Name-agnostic: judged by mapping coverage, so hand-built `LeftShoulder`-style rigs don't false-positive. |
| `ClavicleChainUnmapped` | Warning | No mapped clavicle/shoulder chain (arm raises stop ~50° short — measured 2026-07-02). |
| `FingerChainsUnmapped` / `…PartiallyMapped` | Warning | Fists/hand tracking won't (fully) transfer. |
| `RetargetInstanceNotUsed` | Warning | An RTG exists for the mesh but the component's anim class isn't `VrmVMCRetargetAnimInstance`. |
| `FaceNotDriven` | Warning | A MetaHuman face rides on a VMC-driven body but its anim class consumes no LiveLink subject — the face stays frozen while the body moves. |
| `FaceBridgeMissing` | Warning | The face anim class consumes LiveLink but nothing on the actor publishes the VMC face subject (fine if an iPhone/Live Link Face drives it). |
| `LiveLinkPluginDisabled` | Error | A VMC Face LiveLink component is set up but the engine's LiveLink plugin is disabled. |

## Runtime visibility

`UVrmVMCRetargetAnimInstance` auto-resolve now reports failure instead of silently
T-posing: an on-screen orange message (non-shipping builds) + log warning naming exactly
what could not be resolved (no matching RTG asset vs. no live source rig).

## Known limits

- UE 5.6+ only (controller API shape); on older engines the wizard/lint compile to stubs
  and the menu entries don't register.
- Unknown skeletons (not engine-characterizable, not VRM-resolvable) fail with a pointer to
  the manual recipe in [ik-retargeter-asset-setup.md](ik-retargeter-asset-setup.md).
- The body wizard doesn't touch twist bones. Faces are handled by the separate face wizard
  above (VMC → LiveLink ARKit bridge, [vmc-face-livelink-bridge.md](vmc-face-livelink-bridge.md));
  it requires the engine's LiveLink plugin at runtime and works on any UE 5.x editor build
  (it does not use the 5.6 retargeter controller API).
